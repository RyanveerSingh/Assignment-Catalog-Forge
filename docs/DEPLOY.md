# Deploying CatalogForge for free (Render + Neon)

Everything below is card-free. Total time: about 15 minutes.

## 1. Database: Neon (free)

1. Sign up at https://neon.com with GitHub.
2. Create a project named `catalogforge`. Region: pick the one closest to the Render region you will use (Frankfurt ↔ `eu-central-1`, or Singapore).
3. In the project dashboard open **Connection details**, choose **Pooled connection: off** and copy the connection string. It looks like
   `postgresql://neondb_owner:…@ep-…eu-central-1.aws.neon.tech/neondb?sslmode=require`.
   This is `DATABASE_URL`. Optionally copy the **pooled** variant too (it contains `-pooler`); that is `DATABASE_POOL_URL` and is used only by the storefront's read pool.

Free-tier facts that matter: 1 GB storage, 100 compute-hours/month, compute autosuspends after 5 minutes idle (first query after that takes ~1 s). The worker stops polling when idle so the database can sleep.

## 2. App: Render (free)

1. Sign up at https://render.com with GitHub and grant access to the `Assignment-Catalog-Forge` repository.
2. **New → Blueprint**, select the repository. Render reads `render.yaml` (one free web service, Node 22, health check `/api/health`).
3. When prompted for environment variables, set:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon connection string from step 1 |
   | `DATABASE_POOL_URL` | the pooled Neon string (optional) |
   | `ANTHROPIC_API_KEY` | the API key (optional; without it the app runs in demo mode) |
   | `AI_PROVIDER` | `anthropic` when a key is set, otherwise `mock` |
   | `APP_BASE_URL` | the service URL Render shows, e.g. `https://catalogforge.onrender.com` (edit after the first deploy if needed) |

   `APP_SECRET` is generated by the blueprint; `WORKER_MODE=embedded`, `STORAGE_DRIVER=pg` and `SEED_DEMO=true` are preset.
4. Deploy. The first build takes 3–5 minutes. At boot the app runs migrations under an advisory lock and seeds `demo@catalogforge.dev / demo1234` with two stores. The first boot also imports `new-12.csv` with its photos into the demo store with "Publish products that pass every check" on, so `/store/demo` opens on a stocked shop; later boots leave the store alone.
5. Open the URL, sign in, download `messy-120.csv` and `photos-messy.zip` from the Upload tab, upload them, watch the import.

Free-tier facts that matter: the service spins down after 15 minutes without traffic and wakes in about a minute (the dashboard keeps it awake while open; an unwatched import resumes on the next request exactly like a restart); 750 instance-hours per month cover one always-on service; the instance has 512 MB RAM and a fraction of a CPU, so a 10k-row import is slower than on a laptop.

## 3. Verify

```bash
npx tsx scripts/smoke.ts --base https://catalogforge.onrender.com
```

runs the same end-to-end check used locally (upload → review → approve → storefront in three locales → exports → metrics).

## 4. Adding the real model

In the dashboard, Settings → AI → paste the key (encrypted at rest, per store) or set `ANTHROPIC_API_KEY` on the service. The masthead stops showing "Demo mode". A fresh Anthropic organisation starts at a low rate-limit tier: the 10k sample will hit 429s, which the import shows as "Paused — resuming in X min" and recovers from on its own; Economy mode (Batch API) avoids most of that.

## Alternative: Docker anywhere

```bash
docker compose --profile full up --build
```

starts Postgres, the web service and a separate worker container. Killing the worker container mid-import and starting it again demonstrates resume without data loss.
