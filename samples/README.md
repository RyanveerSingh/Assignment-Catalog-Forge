# Sample supplier sheets

Synthetic, deliberately messy supplier data for manual testing and the evaluation harness.
Everything here except `dump-mysql.sql` is generated by `npm run samples` (`npx tsx scripts/generate-samples.ts [--out samples] [--seed 42] [--verbose]`)
from ~60 product templates in `scripts/lib/catalog.ts`. The files are committed so tests and docs can refer
to specific rows; regenerating with the same seed is byte-identical (CSV, JSON, XLSX and ZIP).
`--verbose` prints which mess was applied to which row of `messy-120`. `dump-mysql.sql` is written by hand.

EC IDs refer to `EDGE-CASES.md`. Row numbers are **1-based data rows** (the first row after the header is row 1),
and are the same for `messy-120.csv` and `messy-120.xlsx`.

## photos-messy.zip

56 entries, all images 600×600 (pastel background from the product colour, SKU and title drawn as text), each under 40 KB:

- 45 named by SKU, e.g. `TC-PL-20.jpg`, `TC-PL-20_2.png`, `tc-pl-30 (1).jpg`, `TC-PL-40.jpg`, `GL-PT-DB_2.jpg`, `OK-ST-SO.png`; mixed JPEG/PNG (C12).
- `subfolder/TC-MG-01.jpg` — an entry inside a folder (A17, C12).
- `TC-MG-02.jpg` and `TC-MG-02_2.jpg` — byte-identical files under two names (C18).
- 3 named by Shopify handle: `linen-cushion-cover.jpg`, `linen-cushion-cover_2.png`, `wool-throw.jpg` (C12).
- `IMG_0001.jpg` … `IMG_0005.jpg` — valid images that match nothing (C13).
- `broken.jpg` — 2 KB of seeded random bytes (C16).
- `logo.svg` (contains a `<script>`) and `readme.txt` — not raster images (A17, C16).

`unmatchedPhotos` in `ground-truth/messy-120.json` lists the last three groups. Rows reference photos in the
`Image` column about 70% of the time (sometimes two, `;`-separated); the rest must be matched by SKU stem or handle.

## Ground truth semantics

- `productKey`: explicit parent/handle when the sheet has one (`TC-PL`, `linen-cushion-cover`), otherwise the SKU
  stem; for single-variant products the SKU itself (`SY-CA-01`). The no-SKU row uses a title slug.
  Bulk keys carry the series suffix: `TC-PL-003` with variants `TC-PL-003-20`.
- `variants[].priceCents` / `currency` are the **true** values before messing (`1.299,00 €` → 129900 EUR,
  `£8` → 800 GBP). A price that was blanked, `0` or `N/A` is `null` (currency `null` too) and the product is
  `needs_review` with `expectedReviewReasons: ["no_price"]`. A conflicting SKU pair keeps the original row's
  price and adds `"sku_conflict"`.
- `categoryPrefix` is always a path from `src/core/ai/taxonomy.ts` (`TAXONOMY`) or a strict prefix of one
  (e.g. `Home & Garden > Decor` for the plant stand, which has no leaf of its own); the generator and the
  test both assert this (EC-D3).
- `variants[].options` are normalised: `{ size: "20 cm", color: "terracotta" }` even when the cell says
  `30cm`, `terracota` or `dunkelblau`.
- `weightGrams` is `null` when the cell was blanked or a placeholder.
- `sourceRows` lists every row that carries the product, including conflict rows, excluding exact duplicates;
  `duplicateRows` lists `{ row, of }` pairs. Together they cover every data row exactly once.
- `language` is the row language (`de`, `fr`); `titleKeywords` and claims are English regardless, because the
  importer must output English.
- `photos` are ZIP entry paths (so `subfolder/TC-MG-01.jpg` keeps its folder).
- Bulk ground truth leaves `allowedClaims`/`negatedClaims`/`photos` empty to save space; SKUs, prices,
  currencies, options, weights, statuses, source rows and duplicate rows are exact.
- `generatedAt` is `seed-<seed>`, not a timestamp, so the files are reproducible.

`scripts/generate-samples.test.ts` regenerates everything into a temp directory and checks row counts, that the
ground truth covers each row exactly once, that duplicates are byte-exact copies, the ZIP contents, and that a
second run is byte-identical.
